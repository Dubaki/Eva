## 0. Стек и общая архитектура

- **Frontend:** Next.js 14 (App Router), React 18, TypeScript, Tailwind CSS, Framer Motion.
- **WebApp UI:** Telegram Mini App (TMA), запускается через @twa-dev/sdk.
- **Backend API:** Next.js Route Handlers (`app/api/...`).
- **БД:** Supabase (Postgres) + Edge Functions на Deno.
- **Бот:** Telegram Bot API через webhook (`/api/webhook/telegram`).
- **Отложенные задачи:** таблица `bot_tasks_queue` + Edge Function `process-bot-queue`, запускаемая каждую минуту через `pg_cron` (или внешний планировщик).

### Таблица `bot_tasks_queue`
> Очередь отложенных задач, которые надо выполнить в боте в определённое время.
> Каждую минуту Edge Function `process-bot-queue` вычитывает `status = 'pending'` и `run_at <= NOW()`, выполняет, ставит `status = 'processed'`.

| Колонка | Тип | Назначение |
|---|---|---|
| `id` | UUID, PK | Внутренний id задачи. |
| `profile_id` | UUID, FK → profiles | Кому относится задача. |
| `tg_id` | bigint | Telegram ID получателя сообщения. |
| `event_type` | text | Тип события: см. ниже. |
| `run_at` | timestamptz | Когда выполнить задачу. |
| `status` | text | `pending` / `processing` / `processed` / `failed`. |
| `error_message` | text | Если `failed` — текст ошибки. |
| `created_at` | timestamptz | Когда задача поставлена. |
| `updated_at` | timestamptz | Когда последний раз обновлена. |

**Типы задач (`event_type`)**:

| Тип | Что делает | Когда ставится |
|---|---|---|
| `start_qualification` | Шлёт связку из 3 сообщений анкеты (см. сообщение №8) и сразу первый вопрос. | Через 24 часа после первого прохождения теста. |
| `send_gift` | Шлёт видео-подарок (когда будет `file_id`). | Через 1 минуту после ответа на 3-й вопрос анкеты. |
| `check_referral_12h` | Проверяет: 2+ друга прошли тест → шлёт смешанную опору. Иначе — «Вижу, твои друзья ещё не прошли тест…». | Через 12 часов после нажатия «Поделиться». |
| `cooldown_reminder` | Шлёт «Хорошая новость! Доступ к тесту снова открыт…». | Через 60 дней после прохождения теста. |

> **Важно:** задача `cooldown_reminder` ставится в очередь сразу при сохранении результата теста. Альтернатива (старая) — Edge Function `send-periodic-reminders`, которая раз в сутки сканирует профили — оставляем как fallback, но основным каналом делаем очередь.

### RPC-функция `submit_test_result_v2`
> Атомарная серверная функция. Вызывается из `/api/test/submit`.

Делает в одной транзакции:
1. INSERT/UPDATE в `test_results` (UPSERT по `tg_id`).
2. UPDATE в `profiles`: `current_step = NULL`, `question_order = NULL`, `reminded_at = NULL`, `last_test_date = NOW()`.
3. Если у пользователя есть `referred_by` и `referral_confirmed = false` — увеличивает `invites_count` пригласившего на 1 и ставит `referral_confirmed = true`.

Возвращает `{referral_processed: bool, inviter_id: uuid | null}`.

## 2. Как приложение узнаёт, что пользователь подписан

> **Главный принцип: проверяем подписку каждый раз при открытии webapp.**
> Кешированное значение `profiles.is_subscribed` — только для аналитики и быстрых запросов в админке.

**Поток:**

1. Пользователь открывает webapp (через кнопку в боте или меню «Тест»).
2. На клиенте срабатывает `Gatekeeper`, который вызывает `GET /api/user/status?tg_id=<...>`.
3. Сервер делает прямой запрос `getChatMember(channelId, tgId)` к Telegram API.
4. Если статус `member` / `administrator` / `creator` — обновляет `profiles.is_subscribed = true` и возвращает `isSubscribed: true`.
5. Если `left` / `kicked` / `restricted` — обновляет `profiles.is_subscribed = false` и возвращает `isSubscribed: false`.
6. Дополнительно сервер возвращает `lastTestDate` для расчёта кулдауна.

**На клиенте `Gatekeeper` решает, что показать:**

```
если !isSubscribed         → страница «Доступ закрыт»     (раздел 3.0)
иначе если daysLeft > 0    → страница «Кулдаун»           (раздел 3.7)
иначе                       → страница «Стартовая»         (раздел 3.1)
```

где `daysLeft = ceil((COOLDOWN_MS - (now - lastTestDate)) / DAY_MS)`,
`COOLDOWN_MS = 60 * 24 * 60 * 60 * 1000`.

### 3.0. Страница «Доступ закрыт»

**Когда открывается:** пользователь не подписан на канал (после проверки в `Gatekeeper`).

**Содержимое:**
- Хедер EvaTest.
- Иконка закрытого замка в glass-card круге (см. дизайн).
- Заголовок: «Доступ ограничен».
- Текст: «Подпишись на мой канал. Там я даю эксклюзивные практики и знания, которых нет в открытом доступе.»
- Кнопка `📢 Подписаться` — открывает `https://t.me/sprosievu`. Свернёт webapp; вернувшись назад, пользователь снова попадёт на эту же страницу.
- Кнопка `✅ Я подписалась` — вызывает `POST /api/subscription/confirm` с `tgId`. Сервер делает `getChatMember` к Telegram. Если подписка подтвердилась:
  1. `profiles.is_subscribed = true`.
  2. **Только при первом подтверждении** (`wasAlreadySubscribed === false`) шлём в чат-бот сообщение №2 «Подписка подтверждена!» (см. `TEXTS.md`).
  3. Перезагружаем `Gatekeeper` → пользователь автоматически попадает на «Стартовую».

  Если не подтвердилось — показываем красный текст: «Подписка не найдена. Пожалуйста, подпишитесь на канал и попробуйте снова.»

- Подпись внизу мелким шрифтом: «Как только подпишешься — откроется доступ ко всему функционалу теста».

### 3.1. Страница «Стартовая»

**Когда открывается:** пользователь подписан, и кулдаун (60 дней с последнего теста) не активен.

**Содержимое (по дизайну):**
- Хедер EvaTest.
- Декоративный блок с цитатой/нарративом.
- Главный текст: «У каждого человека есть внутренняя «опора» — способ держать себя в жизни. Часто эта опора искажается. Снаружи это выглядит как характер или привычки, а на деле — устойчивый механизм, который:» далее три пункта (повторяет сценарии / создаёт проблемы / не даёт выйти из круга), и финал: «Сейчас ты увидишь, какая опора у тебя доминирует».
- Две плашки-стат: `25 вопросов` и `5–7 минут`.
- Блок «Инструкция»: «Отвечай «Да», если откликается, узнаёшь себя или есть телесная реакция. «Нет» — если это не про тебя. Не думай слишком долго, доверяй ощущениям.»
- Кнопка `Начать тест` (внизу страницы) — переход на `/test`.

**Что делает страница в фоне:** ничего, страница чисто декларативная. Прогресс начинается на `/test`.

### 3.2. Страница «Тест»

**Когда открывается:** пользователь нажал «Начать тест» на стартовой.

**Содержимое:**
- Хедер EvaTest со spa-иконкой.
- **Слева сверху** кнопка «Назад» в виде стрелочки `←` — возвращает на предыдущий вопрос (на 1-м вопросе скрыта).
- **Справа сверху** счётчик `3/25` (текущий/всего).
- Под хедером — тонкая линия прогресса: `(текущий + 1) / 25 * 100%`.
- По центру — текст текущего вопроса.
- Внизу — две большие кнопки `Да` / `Нет`.

**Логика поведения:**

1. **При открытии:**
   - `GET /api/test/progress?tgId=<...>`.
   - Если в ответе `isCooldown: true` → редирект на «Кулдаун».
   - Если `question_order === null` → сервер сам генерирует случайный порядок и сохраняет.
   - Если `current_step > 0` → показываем сразу с этого вопроса (восстанавливаем прогресс).
   - Иначе — с 1-го.
   - Если есть `answers` (после возврата) — показываем визуальное состояние «уже выбрано».

2. **Нажатие «Да» (1) или «Нет» (0):**
   - Локально записываем в `answersMap[questionId] = score`.
   - Через 200мс переходим к следующему вопросу.
   - В фоне через `keepalive: true` шлём `PATCH /api/test/progress` с `step = currentIndex + 1`, чтобы сохранить прогресс на случай выхода из приложения.

3. **Нажатие «Назад»:**
   - Уменьшаем `currentIndex`, чистим `selected`.

4. **После 25-го ответа:**
   - На экране показываем оверлей: «Сейчас посчитаю. Это не совсем то, что ты думаешь.» (+ спиннер). **Минимум 2.5 секунды**, даже если сервер ответил быстрее — для UX.
   - Параллельно шлём `POST /api/test/submit` с `{answers, tgId}` и `Authorization: Bearer <jwt>`.
   - Сервер вызывает RPC `submit_test_result_v2`, ставит задачу `start_qualification` в очередь на +24 часа и задачу `cooldown_reminder` на +60 дней.
   - При успехе сервер возвращает `{dominantTrait, referralProcessed}`. Сохраняем в `sessionStorage.eva_result`.
   - **Параллельно** Supabase webhook от вставки в `test_results` триггерит Edge Function `process-bot-notifications`, которая шлёт пользователю в чат-бот сообщение №3 «Твоя опора» (см. п. 4).
   - Редирект на `/result`.

**Удалить из текущего кода:**
- Текст «Осмысляю...» в нижнем спиннере (оставить только «Сейчас посчитаю. Это не совсем то, что ты думаешь.»).

### 3.3. Страница «Результат»

**Когда открывается:** пользователь только что прошёл тест, или открывает webapp после прохождения и попадает сюда напрямую (если есть `test_results`).

**Содержимое (фаза 1 — сразу после теста):**
- Хедер EvaTest.
- **Hero-секция:** картинка соответствующей опоры (см. таблицу маппинга ниже) + плашка «РЕЗУЛЬТАТ ТЕСТА» + заголовок «Ваша доминирующая опора: [Название]».
- **Glass-card с описанием:** полный длинный текст из `lib/constants/results.ts → FULL_RESULTS_TEXTS[trait]` (со всеми блоками «Цена:», «⚡️ Внутри звучит:» и т. д.).
- **Блок «Удивил ли тебя результат?»** с двумя кнопками: `Да` / `Нет`.

**Маппинг буква → название → картинка:**

| Буква | Название | Файл картинки |
|---|---|---|
| S | Героическая опора | `/hero.png` |
| U | Подстраивающаяся опора | `/pleaser.png` |
| P | Перфекционирующая опора | `/perfectionist.png` |
| R | Удерживающая опора | `/stayer.png` |
| K | Контролирующая опора | `/controller.png` |

**Действие при нажатии `Да` или `Нет`:**

> **Никаких модалок-подтверждений!** (старая модалка «Уверена? Ты не сможешь изменить свой ответ» полностью удалена.)

- Сразу появляется задержка 1 секунда (с маленьким спиннером).
- После задержки на той же странице снизу появляется **новый блок** (с вертикальной линией слева, как в дизайне) и страница автоматически **скроллится** к нему.

**Текст блока зависит от выбора:**

- После `Да`:
  > «Это нормально. Более того — это и есть часть механизма. Искажённая опора устроена так, что ты не видишь её напрямую. И именно поэтому снова и снова оказываешься в одних и тех же ситуациях.»
  >
  > «Базовая опора — это только часть картины. Есть ещё смешанные конфигурации, которые активируются в стрессе.»

- После `Нет`:
  > «Это говорит о том, что ты уже явно не новичок в самопознании. Ты видишь этот паттерн, но это ещё не меняет ситуацию.»
  >
  > «Базовая опора — это только часть картины. Есть ещё смешанные конфигурации, которые активируются в стрессе.»

## 5. Реферальная система — полный сценарий

**Шаги жизни реферальной ссылки:**

1. Пользователь A прошёл тест, нажал «Поделиться» на странице «Реферальная ссылка».
2. Сервер шлёт в чат-бот A 2 сообщения с инструкцией и ссылкой `https://t.me/sprosievubot?start=ref_<tgIdA>`.
3. `profiles.shared_at = NOW()` для A.
4. В `bot_tasks_queue` добавляется задача `check_referral_12h` с `run_at = NOW() + 12h`, `tg_id = tgIdA`.
5. Webapp у A закрывается. Ссылка остаётся у A в чат-боте — он может ей делиться сколько угодно и когда угодно.
6. Пользователь B перешёл по ссылке → бот делает upsert в `profiles` с `tg_id = tgIdB` и `referred_by = tgIdA`.
7. B подписывается на канал и проходит тест.
8. RPC `submit_test_result_v2` при сохранении результата B видит `referred_by = tgIdA, referral_confirmed = false` → ставит `referral_confirmed = true` и **+1 к invites_count пригласившему** (A).
9. Тот же сценарий для пользователя C → у A `invites_count = 2`.
10. Edge Function `process-bot-notifications` слушает UPDATE `profiles`. Видит, что `invites_count` стал 2 и раньше был < 2 → шлёт A сообщение №6 «Вторая опора».
11. **Если 12 часов уже прошли** — это путь №2 для сообщения №6, всё работает само.
12. **Если 12 часов ещё не прошли** — обработчик задачи `check_referral_12h` дополнительно проверит флаг (например, новый `mixed_trait_sent`) и не отправит повторно.

**Если через 12 часов `invites_count < 2`:**
- Обработчик задачи `check_referral_12h` шлёт сообщение №5 «Условие не выполнено».
- На этом задача `check_referral_12h` помечается `processed`. Больше не запускается.
- Но логика п. 10 продолжает работать вечно: как только когда-нибудь A наберёт 2 реферала, он получит сообщение №6.

**Условия флага дублирования:**
> Чтобы сообщение №6 не отправилось дважды (один раз обработчиком 12-часов, другой раз watchdog'ом UPDATE) — добавляем в БД флаг `profiles.mixed_trait_sent BOOLEAN DEFAULT FALSE` (новая миграция). Перед отправкой проверяем — если уже `true`, не шлём.
